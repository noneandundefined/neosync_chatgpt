## Neosync HTTP сервер

Это серверная часть системы удаленного управления терминалами Neomatica. Сервер реализован на **Golang** и предоставляет RESTful API для управления пользователями, устройствами, конфигурациями, синхронизацией и аутентификацией. В качестве СУБД используется **PostgreSQL**.

### Технологический стек

- **Golang** (v1.23.0)
- **PostgreSQL** (v14/v16)
- **Gorilla Mux** — роутинг и middleware
- **Swagger (OpenAPI)** — документация API
- **Makefile** — автоматизация сборки и миграций

## Архитектура и структура

cmd/ - Запуск API, миграции, вспомогательные утилиты<br>
└── server/ - Логика запуска HTTP API сервера<br>
└── migrate/ - Миграции БД (SQL)<br>
constants/ - Константы (роли, идентификаторы)<br>
docs/ - Swagger/OpenAPI документация<br>
encryption/ - Утилиты для шифрования<br>
handler/ - HTTP-обработчики (auth, user, device, configuration, sync)<br>
middleware/ - Middleware (логирование, аутентификация)<br>
types/ - Доп. структуры данных<br>
util/ - Вспомогательные утилиты (логгер и др.)<br>
Makefile # Сценарии сборки, запуска, миграций<br>

Полная документация доступна по Swagger UI:
`http://<host>:<port>/api/v1/doc.api/swagger/gui`

## Работа с БД и миграции

- Все миграции SQL хранятся в `cmd/migrate/migrations/`.
- Для применения миграций используйте:
    ```bash
    make migrate-up
    ```
- Для отката:
    ```bash
    make migrate-down
    ```

Перед запуском в production задайте `TRUSTED_PROXIES`: это список IP-адресов
или CIDR доверенных reverse proxy, разделённый запятыми. Только от них сервер
принимает `X-Forwarded-For`; например, для локального nginx используйте
`127.0.0.1,::1`. Если HTTP-сервер доступен напрямую, оставьте переменную пустой.

### Сессии и токены

Сессии хранятся в существующем Redis (`REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`).
Миграция PostgreSQL для сессий не нужна. Ранее выданные токены потребуют повторного
входа. Обновляйте сервер и фронтенд вместе.

Access-токен содержит `session_id` и HMAC IP в `ip_address`; ключи HMAC и
шифрования выводятся из существующего `SUPER_SECRET_KEY` с разными назначениями.
Для каждого access используется случайный nonce AES-GCM. Ключ Redis
`auth:session:<id>` содержит хеш refresh, HMAC IP, пользователя и срок сессии;
`auth:user_sessions:<user_uuid>` — индекс сессий пользователя. Ключи имеют TTL.
Поле PostgreSQL `user_cores.refresh_token` больше не используется для авторизации.
Access действует до 24 часов, сессия — 24 часа без «Запомнить меня» или 30 дней
с ним. Обновление не продлевает общий срок сессии.

Каждый запрос проверяет активность сессии и актуальную роль. Смена IP отзывает
сессию; выход отзывает текущую сессию; успешный сброс пароля отзывает все сессии
пользователя. Вход и сброс пароля сериализуются блокировкой строки пользователя
в PostgreSQL. Общей транзакции Redis/PostgreSQL нет: сессии отзываются до записи
нового пароля. При ошибке Redis пароль не меняется; при последующей ошибке
PostgreSQL сессии остаются отозванными. Смена Wi-Fi/VPN потребует нового входа.
При недоступном Redis авторизация не пропускает запросы; потеря ключей потребует
повторного входа.

При истечении access защищённый маршрут отвечает `401` с
`message.code=auth_refresh_required`, без выполнения обработчика. Фронтенд
вызывает `/auth/check`, который проверяет refresh в Redis и атомарно заменяет
его хеш Lua-скриптом, затем повторяет исходный запрос. Одновременные обновления
согласуются через общий Promise и Web Locks между вкладками (HTTPS/localhost).
Остальные `401` очищают авторизацию. Другие API-клиенты также должны выполнять
обновление последовательно: уже использованный refresh отклоняется.

Проверка авторизации находится в `IsAuthenticatedMiddleware`; обработчики
обращаются к Redis напрямую через `redis.*`.

Ссылка восстановления пароля одноразовая и действует 24 часа. В Redis хранится
только хеш случайного токена; новый запрос ссылки заменяет предыдущую.
Погашение токена и отзыв сессий выполняются атомарно перед фиксацией нового
пароля в PostgreSQL. Повторный запрос откатывает смену пароля. Если фиксация
транзакции не удалась после погашения токена, нужно запросить новую ссылку.
Ссылки, отправленные до перехода на одноразовые токены, больше не принимаются.

## Запуск сервера

```bash
# В режиме разработки
make run

# Сборка бинарника
make

# Запуск тестов
make test
```

## Советы для разработки

- Для добавления новых эндпоинтов — создайте обработчик в handler/ и зарегистрируйте его в cmd/server/routes.go.
- Для новых таблиц — добавьте миграцию в cmd/migrate/migrations/ и структуру в infra/store/models/.
- Для новых сервисов — util/.
- Для новых констант — используйте constants/.
